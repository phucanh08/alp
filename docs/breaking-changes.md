# Breaking changes vs upstream Paseo

alp is a fork of [getpaseo/paseo](https://github.com/getpaseo/paseo). Compatibility with upstream
Paseo clients, daemons, and hosted services is **not** a goal. This file is the running list of
every place where alp intentionally diverges so that upstream and alp cannot interoperate. Append a
row whenever a change breaks upstream compatibility; never delete rows.

Format: one row per change, newest last. `Since` is the alp commit or version that introduced it.

## Hosted services and domains

| Since      | Area               | Upstream                                                   | alp                                            | Effect                                                                                                           |

| 2026-09-25 | web app            | `https://app.paseo.sh`                                     | `https://app-alp.anhlp.com`                    | pairing links and offers point to the alp web app only                                                           |
| 2026-09-25 | hub                | `hub.paseo.sh`                                             | `hub-alp.anhlp.com`                            | CLI `hub` commands and docs default to the alp hub                                                               |
| 2026-09-25 | website/docs       | `paseo.sh`, `www.paseo.sh`                                 | `alp.anhlp.com`                                | in-app links, schema `$id`, update/rosetta callouts, changelog links                                             |

| 2026-09-25 | website/app deploy | upstream Cloudflare account id + KV id hardcoded           | placeholders / `secrets.CLOUDFLARE_ACCOUNT_ID` | deploy workflows need alp-owned Cloudflare secrets before they work                                              |

## SLP defaults on a fresh host

alp runs the SLP (Supervisor / Lead / Peer) workflow by default; a bare upstream Paseo daemon does
none of this without explicit user configuration.

| Since      | Area                      | Upstream                                                                              | alp                                                                                                                                                                                                                                                                                                                                                                                                                                   | Effect                                                                                                                                                                                                                                                                             |
| ---------- | ------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-09-25 | plugins                   | `pluginsEnabled` unset (disabled); no plugin runs without a config entry              | daemon start sets `pluginsEnabled: true` when the key is absent, and always runs the bundled `plugins/slp` plugin with no `plugins.slp` config entry                                                                                                                                                                                                                                                                                  | a fresh daemon runs plugin code the user never opted into; see [docs/plugins.md](../docs/plugins.md#bundled-plugins)                                                                                                                                                               |
| 2026-09-26 | agent providers           | `agents.providers` has no SLP entries                                                 | the daemon seeds no seat provider: a seat is the `slp.role` label on a `claude` or `codex` agent (see [plugins/slp/README.md](../plugins/slp/README.md#seats)). Daemon start deletes `claude-lead`, `claude-peer`, `claude-supervisor`, `codex-lead`, `codex-peer`, `codex-supervisor`, `gemini-lead`, `gemini-peer`, and `gemini-supervisor` from `agents.providers`, matched by exact id, even when the user edited or disabled one | alp builds from 2026-09-25 seeded those nine providers; an agent created on one of them cannot resume after the upgrade, and the Gemini seats have no replacement                                                                                                                  |
| 2026-09-25 | workspace/agents          | opening a workspace or the app never creates an agent on its own                      | a workspace created through the app or CLI gets a Lead agent (`slp.role=lead`, `bypassPermissions`) automatically, and the plugin creates one host-wide Supervisor agent as soon as the app connects to that host, before any sidebar click                                                                                                                                                                                           | new workspaces are not empty; agents exist that Human did not explicitly start                                                                                                                                                                                                     |
| 2026-09-25 | skills                    | host skill directories hold only what the user selected or installed manually         | daemon startup `autoUpdate()` installs the bundled skill set, including the 7 SLP skills (`ask-alp`, `bug-loop`, `goal-griller`, `prompt-leverage`, `sequence-execution-plan`, `smart-commits`, `xia`), even over an explicit "not-installed" selection                                                                                                                                                                               | uninstalling the SLP skills in Settings and restarting the daemon reinstalls them; the selection itself is not cleared                                                                                                                                                             |
| 2026-09-25 | app navigation            | every workspace appears in project lists and can become the remembered last workspace | a workspace with a non-archived Supervisor agent (`slp.role=supervisor`) is hidden from every project list and never becomes the remembered last workspace; the Supervisor button still opens it                                                                                                                                                                                                                                      | cold start, Settings Back, and the last-workspace shortcut return to the last ordinary workspace; a selection saved by an older build is restored until you open another workspace                                                                                                 |
| 2026-09-25 | daemon.mcp                | `daemon.mcp.injectIntoAgents` unset (defaults to `false`)                             | a fresh config starts with `daemon.mcp.injectIntoAgents: true`, and daemon start seeds it into an existing config when the key is absent, without overriding an explicit `false` or `true`                                                                                                                                                                                                                                            | agents alp spawns (SLP Lead, Peer, Supervisor) get `create_agent`, `send_agent_prompt`, `list_agents`, and the rest of the MCP catalog without config changes; see [public-docs/mcp.md](../public-docs/mcp.md#configuration)                                                       |
| 2026-09-25 | plugins/slp seat override | N/A — upstream Paseo has no SLP plugin                                                | `readDefinition` overrides a seat with `<cwd>/.slp/agents/<seat>.md`; it never reads `.claude/agents/<seat>.md`, which is Claude Code's own subagent directory                                                                                                                                                                                                                                                                        | a repo whose only override lived at `.claude/agents/<seat>.md` (e.g. this alp checkout) falls back to the bundled seat definition for app-spawned agents until a matching `.slp/agents/<seat>.md` is added; see [plugins/slp/README.md](../plugins/slp/README.md#seat-definitions) |
| 2026-09-25 | workspace/agents          | a bare `paseo run` creates a new workspace each time; nothing else is created with it | the automatic Lead goes to only one workspace per directory: an app or CLI workspace whose directory already has a live Lead in another active workspace gets none, while `paseo run` still creates the new workspace                                                                                                                                                                                                                 | repeated `alp run` in one directory leaves several workspaces but one Lead; `slp.lead.ensure` still gives a named workspace its own Lead                                                                                                                                           |
| 2026-09-26 | workspace/agents          | N/A — upstream Paseo has no SLP plugin                                                | a `claude`/`codex` agent created directly by Human or by a schedule run, with no `slp.role` label, defaults to Peer and is tagged `slp.origin` (`human` or `schedule`); the Peer's Paseo tool cut also drops `update_agent`, `set_agent_mode`, and `respond_to_permission` (see [plugins/slp/README.md](../plugins/slp/README.md#seats))                                                                                              | a schedule run's agent now carries the same Peer tool cuts and definition as any other Peer, distinguishable from a Human-made one by `slp.origin`; a Peer can no longer reconfigure another agent's provider or mode, or resolve its permission prompts                           |

## Deferred (still upstream values)

| Area                   | Value kept                                         | Why                                                                                                                                     |
| ---------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| project config file    | `paseo.json`                                       | consumed by the upstream Paseo daemon that drives the SLP workflow on this repo, and by i18n strings in 7 locales; rename later if ever |
| hub project dir        | `.paseo/triggers`                                  | hub scaffolding, untouched until hub is re-hosted                                                                                       |
| nix / docker bin names | `paseo-server`, `paseo`, `paseo-docker-entrypoint` | packaging wrappers, Phase 3                                                                                                             |

## Kept compatible on purpose

- `packages/protocol` wire schemas and RPC names: unchanged. Rename never touches field names.
- npm workspace scope `@getpaseo/*` and `PASEO_*` env vars: unchanged (thin rename) so that
  `git merge upstream/main` stays feasible.
